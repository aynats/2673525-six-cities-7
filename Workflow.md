# Как работать над проектом

## Окружение

Для удобства работы над проектом используются инструменты из **Node.js** и **npm**. Все необходимые настройки произведены. Убедитесь, что на рабочем компьютере установлен актуальный LTS релиз Node.js**. Актуальная версия **Node.js** указана в файле `package.json` в поле `node`. Затем, в терминале, перейдите в директорию с проектом и _единожды_ запустите команду:

```bash
npm install
```

Команда запустит процесс установки зависимостей проекта из **npm**.

### Сценарии

В `package.json` предопределено несколько сценариев.

#### Скомпилировать проект

```bash
npm run compile
```

Создаст директорию `dist` и скомпилирует проект.

#### Удалить скомпилированный проект

```bash
npm run clean
```

Удаляет директорию `dist`. Используется перед компиляцией.

#### Собрать проект

```bash
npm run build
```

Выполняет сборку проекта: удаляет ранее скомпилированный проект и компилирует заново.

#### Проверить линтером

```bash
npm run lint
```

Запуск проверки проекта статическим анализатором кода **ESLint**.

Линтер проверяет файлы только внутри директории `src`.

**Обратите внимание**, при запуске данной команды, ошибки выводятся в терминал.

#### Запустить ts-модуль без компиляции

```bash
npm run ts -- <Путь к модулю с ts-кодом>
```

Пакет `ts-node` позволяет выполнить TS-код в Node.js без предварительной компиляции. Используется только на этапе разработки.

#### Запустить проект

```bash
npm start
```

В процессе запуска проекта будет выполнен процесс «Сборки проекта» и запуска результирующего кода.

#### Запустить CLI

```bash
npm run cli -- <команда> [аргументы]
```

Запускает Command Line Interface приложения из скомпилированного файла `dist/main.cli.js`. Используется для работы с тестовыми данными: импорта из TSV-файлов и генерации новых наборов.

**Обратите внимание**, сценарий требует предварительной сборки проекта (`npm run build`). Если `dist` отсутствует или устарел, сначала выполните сборку.

Поддерживаемые команды:

| Команда | Назначение |
|---|---|
| `--help` | Показывает список доступных команд и примеры использования. Вызывается автоматически, если не передать никаких аргументов. |
| `--version` | Выводит версию приложения, считанную из `package.json`. |
| `--import <path>` | Импортирует данные из TSV-файла по указанному пути и выводит результат в консоль. |
| `--generate <n> <path> <url>` | Генерирует `n` тестовых предложений, запрашивая исходные данные с JSON-сервера по адресу `<url>`, и сохраняет их в TSV-файл по пути `<path>`. |

Примеры:

```bash
npm run cli -- --help
npm run cli -- --version
npm run cli -- --import ./mocks/mock-data.tsv
npm run cli -- --generate 10 ./mocks/generated-data.tsv http://localhost:3123/api
```

**Важно.** Между `npm run cli` и командой приложения обязателен разделитель `--`. Без него флаги вроде `--version` перехватит сам npm и выведет собственную версию вместо версии приложения. Сравните:

```bash
npm run cli --version         # выведет версию npm (например, 10.8.2) — не то
npm run cli -- --version      # выведет версию приложения (4.0.0) — то, что нужно
```

Альтернативный способ запуска без npm — напрямую через Node.js:

```bash
node ./dist/main.cli.js --help
node ./dist/main.cli.js --import ./mocks/mock-data.tsv
```

#### Запустить мок-сервер

```bash
npm run mock:server
```

Поднимает тестовый REST API на основе **json-server**. Данные для сервера берутся из файла `mocks/mock-server-data.json`. Сервер слушает порт **3123**.

Например, после запуска по адресу `http://localhost:3123/api` будет доступен JSON с заготовками данных (заголовки, описания, ссылки на изображения, имена пользователей и т. д.). Используется командой `--generate` для получения исходных данных при формировании тестовых наборов.

**Обратите внимание**, сервер работает в отдельном терминале. Не закрывайте его, пока не закончите работу с командами, которые обращаются к этому URL.

## Структура проекта

### Директория `src`

Исходный код проекта: компоненты, модули и так далее. Структура директории `src` может быть произвольной.

### Файл `Readme.md`

Инструкции по работе с учебным репозиторием.

### Файл `Contributing.md`

Советы и инструкции по внесению изменений в учебный репозиторий.

### Остальное

Все остальные файлы в проекте являются служебными. Пожалуйста, не удаляйте и не изменяйте их самовольно. Только если того требует задание или наставник.
